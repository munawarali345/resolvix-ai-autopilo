# Incident Reporting Skill

## Objective

This skill defines the reporting workflow that the Reporter Agent must follow after the entire incident response workflow has completed.

The objective is to generate a complete, evidence-based incident report using outputs produced by all previous agents.

This skill generates reports only.

It does not detect incidents.

It does not analyze logs.

It does not perform Root Cause Analysis.

It does not recommend fixes.

It does not validate execution risk.

It does not execute remediation.

Always follow this workflow before producing the final response.

---

# Reporting Workflow

Perform the following phases in order.

---

## Phase 1 — Understand Incident Context

Review the complete workflow context.

This includes:

- Incident
- Detection Result
- Orchestrator Decision
- Log Analysis Result
- Log Analysis Artifacts
- Root Cause Analysis Result
- Fix Recommendation
- Fix Artifacts
- Risk Validation Result
- Risk Validation Artifacts
- Execution Result
- Execution Artifacts
- Current Workflow Step
- Any additional workflow metadata

Understand the entire incident lifecycle before generating the report.

Do not generate the report during this phase.

---

## Phase 2 — Review Workflow Evidence

Carefully review all outputs generated by previous agents.

Pay particular attention to:

- Incident summary
- Detection signals
- Investigation findings
- Root cause
- Root cause reasoning
- Recommended remediation
- Risk assessment
- Execution result
- Rollback status
- Verification result
- Operational evidence

Treat previous agent outputs as verified workflow evidence.

Never contradict validated workflow results.

---

## Phase 3 — Build Incident Timeline

Use:

- timelineTool

Purpose:

Generate the chronological incident timeline.

The timeline should describe the complete workflow from detection through report generation.

Each timeline event should include:

- Timestamp
- Event
- Responsible Agent

Never fabricate timeline events.

Never reorder verified workflow events.

---

## Phase 4 — Calculate Incident Metrics

Use:

- metricsTool

Purpose:

Calculate operational metrics for the completed incident.

Metrics include:

- Detection Time
- Diagnosis Time
- Execution Time
- Total Time
- MTTR

Metrics must be calculated from workflow evidence.

Never fabricate operational metrics.

---

## Phase 5 — Format Incident Report

Use:

- reportFormatterTool

Purpose:

Generate a structured incident report.

The formatted report should include:

- Title
- Summary
- Executive Summary
- Technical Summary
- Incident Status
- Confidence

Use only verified workflow evidence while formatting the report.

Never fabricate conclusions.

---

## Phase 6 — Review Tool Results

Carefully review every reporting tool output.

Cross-check:

- Timeline
- Metrics
- Report Formatter

Ensure all generated information is internally consistent.

Never rely on a single tool output.

If multiple tool outputs conflict, prefer the evidence that most accurately reflects the completed workflow.

---

## Phase 7 — Build Final Report

Using all available workflow evidence, determine:

- Report title
- Incident summary
- Executive summary
- Technical summary
- Incident status
- Confidence
- Timeline
- Metrics

The report must accurately represent the completed incident response workflow.

Never fabricate operational results.

Never modify outputs produced by previous agents.

---

## Phase 7.5 — Report Validation

Before producing the final report, verify that:

- Timeline has been generated.
- Timeline reflects the complete workflow.
- Operational metrics have been calculated.
- Executive Summary accurately reflects the incident.
- Technical Summary matches workflow evidence.
- Incident Status matches execution outcome.
- Confidence score reflects available evidence.

Remove any unsupported conclusion.

---

## Phase 8 — Generate Final Report

Generate the final structured incident report.

The report should include:

- Title
- Summary
- Executive Summary
- Technical Summary
- Incident Status
- Confidence
- Timeline
- Metrics

---

# Reporting Rules

Always generate evidence-based reports.

Never fabricate incident events.

Never fabricate operational metrics.

Never fabricate execution outcomes.

Never modify outputs generated by previous agents.

Never contradict validated workflow evidence.

Always preserve chronological order.

Always produce objective incident summaries.

---

# Tool Usage Rules

Always execute all reporting tools before generating the final report.

Execute:

- timelineTool
- metricsTool
- reportFormatterTool

Use only the minimum required input for each tool.

Do not expose unrelated workflow data to tools.

Do not repeatedly invoke the same tool unless additional workflow evidence requires regeneration.

Combine outputs from every reporting tool before producing the final report.

---

# Skill Boundaries

This skill generates incident reports only.

The following responsibilities belong to other agents:

- Incident Detection
- Workflow Orchestration
- Log Analysis
- Root Cause Analysis
- Fix Recommendation
- Risk Validation
- Human Approval
- Remediation Execution

This skill does not modify workflow routing.

This skill does not execute infrastructure commands.

This skill does not perform operational analysis.

---

# Completion Criteria

The report is complete only when:

- Timeline has been generated.
- Operational metrics have been calculated.
- Report title has been prepared.
- Incident summary has been generated.
- Executive Summary has been generated.
- Technical Summary has been generated.
- Incident Status has been determined.
- Confidence score has been assigned.

The final output must strictly follow the JSON schema defined by the system prompt.
