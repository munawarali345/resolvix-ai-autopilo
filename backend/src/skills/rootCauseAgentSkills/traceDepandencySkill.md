# Trace Dependencies Skill

## Objective

This skill defines the investigation workflow used by the Root Cause Agent.

Its objective is to determine the most probable root cause of an incident by reasoning over structured evidence produced by previous stages.

Always use the available investigation evidence before generating a conclusion.

---

# Investigation Workflow

Perform the following phases in order.

---

## Phase 1 — Understand Investigation Context

Review all available investigation inputs.

This includes:

- Incident
- Raw Logs (reference only)
- Detection Result
- Current Workflow Step
- Log Analysis Result
- Log Analysis Artifacts

Treat every available input as supporting evidence.

Do not begin reasoning before reviewing all available information.

---

## Phase 2 — Review Investigation Evidence

Carefully inspect all evidence produced by the Log Analyzer.

This includes:

- Incident summary
- Key findings
- Affected services
- Failure pattern
- Investigation hints

Also inspect all available structured artifacts.

Examples include:

- Extracted ERROR logs
- Incident timeline
- Grouped log events
- Service dependency map

Never ignore structured evidence.

Treat Log Analysis outputs as the primary investigation evidence.

Use raw logs only when additional verification is required.

---

## Phase 3 — Correlate Evidence

Compare information collected from different sources.

Look for:

- Relationships between affected services
- Error propagation
- Repeated failures
- Timeline correlations
- Dependency relationships
- Failure sequence

Build logical relationships only from available evidence.

Do not invent missing relationships.

---

## Phase 4 — Identify Root Cause

Using all available evidence, determine the most probable root cause.

The identified root cause must explain:

- Why the incident occurred
- Why the observed failures happened
- Why affected services behaved as observed

Only identify a root cause that is supported by evidence.

---

## Phase 5 — Explain Reasoning

Clearly explain why the identified root cause is the most probable explanation.

The reasoning should reference evidence collected during investigation.

Avoid unsupported assumptions.

---

## Phase 6 — Confidence Evaluation

Estimate confidence based on evidence quality.

Higher confidence should only be assigned when:

- Multiple evidence sources agree
- Timeline supports the conclusion
- Failure pattern matches the identified cause

Reduce confidence whenever evidence is incomplete or conflicting.

---

## Phase 7 — Supporting Evidence

List the most important evidence supporting the identified root cause.

Evidence should be concise and directly related to the conclusion.

---

# Investigation Rules

Always perform evidence-based reasoning.

Never guess.

Never fabricate information.

Never invent services.

Never invent dependencies.

Never ignore investigation evidence.

Never contradict verified Log Analysis results.

If evidence is insufficient, produce the best-supported conclusion with lower confidence.

---

# Tool Usage Rules

No runtime tools are available for this skill.

Perform reasoning only using the provided investigation inputs.

Do not assume external systems or missing data.

---

# Completion Criteria

The investigation is complete only when:

- Root cause is identified.
- Reasoning is provided.
- Confidence score is assigned.
- Supporting evidence is listed.

The final output must populate every field of **RootCauseAgentOutput**.

The final output must strictly follow the JSON schema defined by the system prompt.
