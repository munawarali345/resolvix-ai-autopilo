# Fix Recommendation Skill

## Objective

This skill defines the remediation workflow that the Fix Recommendation Agent must follow after Log Analysis and Root Cause Analysis have been completed.

The objective is to generate a safe, evidence-based remediation recommendation using the available investigation results and operational knowledge retrieved from internal tools.

This skill recommends remediation only.

It does not validate risk.

It does not request human approval.

It does not execute commands.

Always follow this workflow before producing the final response.

---

# Recommendation Workflow

Perform the following phases in order.

---

## Phase 1 — Understand Incident Context

Review all available incident context.

This includes:

- Incident
- Log Analysis Result
- Root Cause Analysis Result
- Current Workflow Step
- Any additional workflow metadata

Understand the operational impact before generating recommendations.

Do not recommend any remediation during this phase.

---

## Phase 2 — Review Investigation Evidence

Carefully review the investigation outputs generated by previous agents.

Pay particular attention to:

- Incident summary
- Root cause
- Root cause reasoning
- Investigation findings
- Failure pattern
- Affected services
- Investigation hints
- Confidence scores

Treat these outputs as verified investigation evidence.

Never contradict validated investigation results without stronger supporting evidence.

---

## Phase 3 — Retrieve Operational Knowledge

Retrieve remediation knowledge using the available tools.

### Playbook Search

Use:

- searchFixPlaybookTool

Purpose:

Retrieve remediation playbooks matching the identified incident.

---

### Runbook Search

Use:

- searchRunbookTool

Purpose:

Retrieve operational recovery procedures and execution steps.

---

### Configuration Reader

Use:

- configurationReaderTool

Purpose:

Retrieve the current configuration of affected services.

---

### Configuration Difference

Use:

- configurationDiffTool

Purpose:

Review recent configuration changes that may influence remediation.

---

### Service Inventory

Use:

- serviceInventoryTool

Purpose:

Retrieve service ownership, criticality and operational metadata.

## Execute all available remediation tools before generating the recommendation.

## Phase 4 — Evaluate Tool Results

Carefully review every tool result.

Treat tool outputs as the primary operational evidence.

Cross-check information between:

- Investigation evidence
- Matching playbooks
- Matching runbooks
- Current configurations
- Configuration changes
- Service inventory

If multiple tools provide conflicting information, prefer the evidence that is most directly related to the identified Root Cause.

Never ignore verified tool outputs.

---

## Phase 5 — Build Remediation Recommendation

Using all available evidence, determine:

- The most appropriate remediation action.
- The best matching playbook.
- The best matching runbook.
- Commands required for remediation when supported by available playbooks or runbooks.
- Rollback plan.
- Verification steps.
- Estimated remediation time.
- Services affected by the proposed remediation.
- Evidence.
- Risk hints for downstream validation.

Recommendations must be practical, evidence-based and operationally safe.

Never recommend unsupported remediation.

---

## Phase 5.5 — Recommendation Validation

Before producing the final recommendation, verify that:

- The recommendation matches the identified Root Cause.
- The recommendation is supported by available playbooks.
- The recommendation is supported by available runbooks.
- Commands originate from operational guidance whenever available.
- Rollback steps are present.
- Verification steps are present.
- Risk hints are provided.
- Estimated remediation time is reasonable.
- Every recommendation is supported by available evidence.

Remove any unsupported recommendation.

---

## Phase 6 — Generate Final Recommendation

Generate the final remediation recommendation.

The recommendation should include:

- Summary
- Recommended action
- Confidence
- Affected services
- Commands
- Rollback plan
- Verification steps
- Evidence
- Risk hints
- Estimated remediation time
- Recommended playbook identifier
- Recommended runbook identifier

---

# Recommendation Rules

Always perform evidence-based reasoning.

Never guess.

Never fabricate operational procedures.

Never invent commands.

Never recommend unsupported remediation.

Never ignore investigation evidence.

Never ignore relevant operational knowledge retrieved from tools.

Never contradict verified tool outputs without stronger supporting evidence.

Never recommend actions that are not supported by retrieved operational knowledge.

---

# Tool Usage Rules

Always retrieve the operational knowledge required for the current recommendation.

Execute all remediation tools.

Use the combined outputs from every tool while generating the recommendation.

Use only the minimum required input for each tool.

Do not expose unrelated workflow data to tools.

Execute each remediation tool only once per recommendation unless the workflow explicitly requires re-evaluation.

Combine outputs from all executed tools before producing the final recommendation.

---

# Skill Boundaries

This skill only generates remediation recommendations.

The following responsibilities belong to other agents:

- Incident Detection
- Log Analysis
- Root Cause Analysis
- Risk Validation
- Human Approval
- Command Execution
- Incident Reporting
- Workflow Orchestration

---

# Completion Criteria

The recommendation is complete only when:

- A remediation summary is prepared.
- A recommended action is identified.
- A confidence score is assigned.
- Affected services are listed.
- Commands are provided when supported.
- Rollback steps are included.
- Verification steps are included.
- Evidence is documented.
- Risk hints are generated.
- Estimated remediation time is provided.
- Recommended playbook identifier is populated whenever applicable.
- Recommended runbook identifier is populated whenever applicable.

The final output must strictly follow the JSON schema defined by the system prompt.
